## 執行摘要 (Executive Summary)

社群在日常發起聚會、出遊或活動時，經常遭遇「聊天洗版混亂、空檔難以彙整、地點意見分歧」三大痛點。SquadUp 旨在提供極簡順暢的揪團流程：免登入並可以在 10 分鐘內快速建團、向後推算 2 個月的月曆熱度圖、自動運算最佳時段 Top 3 及候選地點投票。

在商業模式上，以輕量工具累積社群流量，並引進 Google 會員機制、B2B 商業展演活動日程套入及票務聯盟分潤，打造「發起 — 協調 — 定案 — 購票」的一站式閉環服務。

## 5W2H1E 企劃架構分析

### 1. Why（為什麼要做？專案緣起與目標效益）

- **解決痛點**：
    - **通訊軟體統計困難**：LINE、Discord 的純文字或簡易投票功能無法處理「多天 × 跨時段」的複雜矩陣排列。
    - **既有工具門檻過高**：海外常見排程工具（如 Doodle、When2meet、調整さん）介面老舊、欠缺社群卡片整合（Open Graph），且未串聯地點決策與線下活動內容。
- **產品願景**：成為亞太及全球社群使用者在日常聚餐、桌遊密室、展演揪團時的首選排程工具。
- **關鍵成果指標 (KPI)**：
    - 上線首季累積 **10,000+** 個有效發起團體。
    - 單一活動的平均填寫參與率達 **80%** 以上。
    - 社群轉發係數 **K-factor > 1.2**（病毒式擴散效應）。

---

### 2. What（做什麼？產品核心範疇與功能清單）

堅持「操作極簡、視覺直覺、決策快速」的原則，功能模組劃分如下：

| 功能模組 | 細部規格與運作邏輯 |
| --- | --- |
| **發起建團 (Host)** | 必填主題與主辦人暱稱；選填最多 3 個候選地點（支援 Google Maps 連結與會員生活圈快捷帶入）；選填 3~8 碼參加密碼；自訂有效期限（訪客 3/5/7 天，會員可達 30 天）。支援「粗略時段（全天/上午/下午/晚上）」與「精細區間」設定。 |
| **時程熱度圖 (Heatmap)** | 顯示從當天起向後推算 2 個月的月曆檢視。點選日期彈出時段選單。依據參加者重疊度呈現深淺色階（綠色漸層），一眼辨識熱門日期。 |
| **最佳時段排行 (Top 3)** | 系統即時比對所有人空檔，自動計算並列出可出席人數最多的前 3 名時段，並標註具體名單（僅 1 人有空時不予顯示）。 |
| **地點決策 (Location)** | 單一地點直接顯示資訊與地圖按鈕；多地點開放單選投票；未輸入則顯示「地點尚未確定」。 |
| **分享與驗證 (Share)** | 支援 Web Share API 一鍵分享至 LINE、Discord 等通訊軟體；配置動態 OG Tag 顯示即時參與人數；非會員以 LocalStorage 識別，防範惡意竄改並支援二次修改。 |

### 3. Who（誰是目標對象與使用者角色定義？）

- **目標族群 (Target Audience)**：
    - 社群核心主辦人（桌遊團長、社團幹部、專案 PM、常態聚餐召集人）。
    - 頻繁參與線下活動的年輕族群（展覽愛好者、ACG 同好、大學生、年輕上班族）。
- **角色與權限分級**：
    - **訪客 (Guest)**：免登入直接建團或填寫，連結時效 3/5/7 天，受限於單一瀏覽器 LocalStorage 管理，瀏覽標準版位廣告。
    - **一般會員 (Free Member - Google 登入)**：跨裝置儀表板（我主辦的 / 我參加的）、活動效期最長 30 天、具備主辦人剔除亂入者並重算票數權限、個人常用生活圈快選。
    - **付費訂閱會員 (Pro Member)**：全站完全免廣告、活動最長 1 年、匯出 CSV/Excel 完整報表、專屬活動封面。

---

### 4. Where（在哪裡運作？通訊平台與運行環境）

- **終端平台**：響應式網頁 (Responsive Web Design, RWD)，專門針對手機端直向操作、手勢滑動與彈出鍵盤進行防呆體驗優化。
- **傳播場域**：LINE 群組、Discord 伺服器頻道、Facebook 社團、Instagram 限時動態外部連結。
- **技術運行環境**：部署於全球邊緣運算網路（Edge Network / Vercel），後端統一以 **UTC 時間**儲存，前端自動判讀用戶裝置時區進行精準轉換，消除跨國時差爭議。

---

### 5. When（時程規劃與里程碑管理）

專案採三階段敏捷推進：

```
Phase 1: MVP 核心 (第 1~4 週)
├── 免登入建團與參加
├── 月曆熱度圖 (Heatmap)
├── Top 3 最佳時段演算
├── 地點單選投票
└── 中/英/日多語系切換

Phase 2: 會員生態 (第 5~8 週)
├── Google OAuth 一鍵登入
├── 個人歷史儀表板
├── 主辦人控場踢人機制
└── 拍板定案並產生 Google 日曆 / .ics 邀請

Phase 3: 商業擴展 (第 9~12 週)
├── 商業展演活動日程範本匯入
├── 售票平台聯盟行銷導購
└── Pro 付費去廣告會員訂閱機制
```

### 6. How（如何執行？技術選型與系統架構）

- **前端框架**：`Next.js (App Router)` + `TypeScript` + `Tailwind CSS`。
- **社群轉發動態渲染**：藉由 SSR (Server-Side Rendering) 動態產生 Open Graph Meta 標籤與即時預覽圖。
- **後端與資料庫**：Next.js Server Actions / API Routes 搭配 `PostgreSQL`（Prisma / Drizzle ORM）。
- **即時通訊**：採用 Server-Sent Events (SSE) 或 `Supabase Realtime`，在群組多人同時投票時即時刷新月曆熱度與排行榜。
- **多語系 (i18n)**：採用 `next-intl` 整合繁體中文、英文與日文，首次載入依 `navigator.language` 自動切換。

---

### 7. How Much（成本結構與定價策略）

- **初期運營成本 (Cost)**：
    - 雲端伺服器與資料庫（初期免費或低階層級約 $20 ~ $50 USD / 月）。
    - 網域租用與 Google OAuth API 配額（低固定成本）。
- **多元營收來源 (Revenue Streams)**：
    - **廣告變現**：於頁尾固定橫幅與送出完成頁置入廣告，確保核心排程流程不被干擾。
    - **訂閱會員 (Pro)**：
        - 專業月費方案：$2.99 USD / 月（享無限去廣告、連結最長 1 年保留、匯出報表）。
    - **展演導購分潤 (Affiliate)**：對接 Klook、KKday、Accupass 等售票平台，用戶定案後點擊購票享有 3% ~ 8% 導購分潤；或向策展廠商收取 B2B 推薦活動刊登費。

### 8. Evaluation（成效評估與風險控管）

| 潛在風險 (Risks) | 影響程度 | 具體防禦與因應措施 |
| --- | --- | --- |
| **惡意洗板、灌水或竄改** | 中 | 採用 LocalStorage 裝置 Token 防呆；提供主辦人一鍵踢除惡意者並自動即時扣除票數重算。 |
| **跨時區參與導致時間錯亂** | 高 | 資料庫所有時間一律存儲 UTC 格式；前端依據瀏覽器環境動態在地化換算。 |
| **新服務冷啟動流量不足** | 高 | 建立「熱門展演情報」範本庫（如：當季動漫展、藝術特展、快閃店），讓使用者「看見活動就能一鍵揪團」，降低發起門檻並帶動社群自發轉載。 |
| **廣告干擾破壞填寫體驗** | 中 | 嚴格禁止滿版蓋版廣告與內嵌月曆廣告；僅限於非關鍵互動版位（頁尾、完成頁）展示。 |
