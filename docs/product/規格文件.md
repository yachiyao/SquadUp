# 揪一下 | 線上即時揪團服務專案規格與流程規劃書

## 1. 產品概述與定位

本產品為一款輕量、直覺且跨平台的線上揪團與時間/地點協調工具。使用者無需繁瑣流程即可在短時間內發起揪團活動，並透過專屬連結於 LINE、Discord 等社群軟體擴散。平台透過視覺化熱度圖、自動歸納最佳時段與地點投票機制，解決朋友聚會、展演揪團、桌遊活動等「喬時間、選地點」的痛點。完美適配PC端與手機端的RWD網站。

## 2. 系統架構與使用者角色層級

#### 使用者分級架構：

| 訪客 (Guest) |   1. 免登入快速發起 / 參加活動
  2. 活動連結有效期限：3 / 5 / 7 天
  3. 依賴瀏覽器 LocalStorage / 暫存金鑰管理
  4. 觀看標準廣告版位 |
| --- | --- |
| 一般會員 (Free Member) |   1. Google OAuth 2.0 一鍵註冊 / 登入
  2. 歷史活動紀錄（我主辦的 / 我參加的）
  3. 跨裝置編輯與管理活動（連結有效期限最長可達 30 天）
  4. 可剔除惡意參加者並即時重算票數
  5. 可設定常用生活圈，快速帶入推薦
  6. 觀看標準廣告版位 |
| 付費訂閱會員 (Pro Member) |   1. 完全去除全站廣告
  2. 活動連結可保留至 1 年有效
  3. 可匯出 CSV / Excel 完整報表
  4. 可客制封面圖 |

## 3. 使用者流程與功能規格

### 3.1 首頁（Landing Page）

1. **多語系切換：**
    - 位於網頁右上角，提供繁體中文（zh-TW）、英文（en）、日文（ja）切換。
    - 首次訪問自動讀取 `navigator.language` 呈現對應語系，後續偏好儲存於 `localStorage`。
    - 中文名稱為：揪一下
    - 英文名稱為：Squad Up
    - 日文名稱為：スコッドアップ
2. **身分入口與主視覺：**
    - **主辦人入口（核心按鈕）：** 【我是主辦人 / 發起新揪團】。
    - **參加者入口：** 【輸入揪團代碼進入】（或直接點擊歷史暫存紀錄快速進入）。
    - **會員狀態：** 右上角顯示 Google 登入按鈕；已登入者顯示個人頭像與「我的揪團紀錄」入口。

### 3.2 發起揪團流程（主辦人端）

1. **活動資訊填寫表單：**
    - **活動主題（必填）：** 文字輸入框。
    - **地點候選（選填，最多 3 個）：**
        - 支援輸入店名 / 地標，並可選填 Google Maps 連結或備註。
        - 會員可直接點選個人設定的「常用生活圈」快捷帶入。
        - 若未填寫任何地點，前台顯示「地點尚未確定」；若僅填 1 個，前台直接顯示該地點而不開啟投票。
    - **參加密碼（選填）：** 可設定 3 ~ 8 位數字或字元密碼。
    - **參加人數上限（必填）：** 主辦人建立活動時設定可參加人數，輸入整數 1～20，預設 20 人。上限計入主辦人本人；主辦人建立活動後即占 1 個名額，不需另外報名。前端提供範圍提示與驗證，後端也須拒絕不在範圍內的值。
    - **連結有效天數：**
        - 訪客可選：3 天、5 天、7 天。
        - 會員可選：最長可延伸至 30 天（Pro 訂閱會員可自訂更長期限至1年）。
    - **時段模式選擇：** 粗略模式（全天、上午、下午、晚上）或具體時間區間。
    - **主辦人暱稱（必填）：** 文字輸入框。若已登入 Google 則自動帶入預設名稱。
2. **生成與分享活動頁：**
    - 點擊【生成揪團連結】後，後端建立活動記錄並產生專屬 URL（例如：`group.domain/g/{activityId}`）。
    - 轉移至專屬分享頁面，提供：
        - 連結一鍵複製按鈕。
        - Web Share API 原生整合（支援一鍵轉發至 LINE、Discord 等）。
        - 自動配置 Open Graph Meta Tags（讓社群預覽卡片顯示活動標題、目前人數等動態資訊）。

### 3.3 活動協調與填寫頁面（主辦人與參加者通用介面）

專屬活動頁面由三大核心模組構成：

| 【活動資訊區】 | 活動名稱
主辦人 | （若為會員主辦人：管理設定 / 提前結案）
倒數有效天數、目前參加人數 / 人數上限；額滿時顯示「已額滿」 |
| --- | --- | --- |
| 【月曆時程熱度圖】
  • 顯示從當日往後 2 個月的月曆檢視。
  • 色階依填寫人數深淺顯示（綠色漸層），一眼看出最高人氣日期。
  • 點選日期彈出時段選單：【全天】或各指定【時段】。
  • 填寫暱稱後送出，當天時段即標記該暱稱。 |  |  |
| 【最佳時段排行榜 Top 3】
  • 即時歸納重疊人數最多的前 3 個時段
  • 標示具體人數與可參加者暱稱名單。
  • 僅 1 人有空時不予顯示排行榜。 | 【地點投票 / 資訊區】
  • 單一地點：直接顯示地址與地圖按鈕。
  • 多地點：列出候選項目供參加者單選投票。
  • 無地點：顯示「地點尚未確定」。 |  |
| 【頁尾廣告 / 合作推薦 Banner】（付費會員免除） |  |  |
1. **參加者身分驗證與編輯：**
    - 若活動設有密碼，首次載入頁面時彈出 Modal 驗證密碼。
    - 非會員填寫時，前端發放 Token 存入該裝置 `LocalStorage`，同裝置再次開啟時自動進入「編輯上次送出」狀態，避免重複灌水或同名混淆。
    - 名額以成功加入活動的不同參加者計算，與填寫幾個日期、時段或地點無關；主辦人計入其中。只有輸入暱稱、通過密碼驗證或開啟連結，不占名額；首次成功送出報名資料後才占 1 個名額。
    - 額滿後，尚未加入者仍可查看活動資訊與協調結果，但不可新增報名、時段或地點票；畫面顯示「已額滿（20/20）」等實際人數與上限。已加入者可繼續編輯自己的資料，不增加名額。
    - 首次報名送出時，後端須在同一筆原子交易中確認活動仍可報名、確認身分尚未占位、檢查目前人數小於上限，然後建立參加紀錄；同時送出造成額滿時，僅容許剩餘名額數量的請求成功，其餘回傳額滿並刷新畫面。前端顯示的人數僅供參考，不作為是否可加入的最終判斷。
2. **主辦人管理功能（需會員權限）：**
    - **踢除參加者：** 主辦人可在名單點擊移除特定參加者，系統同步扣除其所投的日期與地點票數，並即時重算 Top 3 推薦時段。
    - **名額釋放：** 被踢除者的參加紀錄與投票移除後釋出 1 個名額，活動頁即時更新人數並恢復可報名狀態；主辦人本人的名額不可透過踢除釋放。本版建立後不可修改人數上限。
    - **拍板定案（Finalize）：** 鎖定投票表單，產生確定行程並提供加入 Google 日曆 / 匯出 `.ics` 檔功能。

### 3.4 參加人數上限驗收情境（v1.3）

1. 主辦人建立活動時可選 1～20 人；未調整時採 20 人。輸入 0、21、小數或非數字，前後端均拒絕建立。
2. 設為 3 人時，建立後顯示 1/3；兩位不同參加者首次成功送出後依序顯示 2/3、3/3，第三位收到額滿提示且資料不寫入。
3. 已加入者在 3/3 時修改自己的時段或地點，仍可成功送出，參加人數維持 3/3；同一身分重複送出也不重複占位。
4. 兩人同時競爭最後一個名額時，只能有一人加入成功，結果不超過設定上限。
5. 會員主辦人移除一位參加者後，人數由 3/3 變為 2/3，原票數同步扣除，新參加者可加入；活動拍板定案後仍維持既有鎖定規則。

## 5. 技術選型建議

1. **前端工程：**
    - **框架：** Next.js (React) + TypeScript，利用 App Router 處理動態路由與 Server-Side Rendering (SSR)，確保社群分享（LINE/Discord OG Tags）正確抓取活動資訊。
    - **樣式與元件：** Tailwind CSS + Lucide React 圖示庫。
    - **多語系（i18n）：** `next-intl` 或 `react-i18next`，統一管理繁中、英文、日文字典檔。
2. **後端與資料庫：**
    - **API / 後端：** Next.js Server Actions / API Routes，搭配 Node.js。
    - **資料庫：** PostgreSQL（搭配 Prisma 或 Drizzle ORM），時間資料一律儲存 UTC 格式。
    - **驗證系統：** NextAuth.js (Auth.js) 整合 Google OAuth。
    - **即時更新：** Supabase Realtime 或 Server-Sent Events (SSE)，當多人同時開啟網頁投票時，熱度圖與票數即時刷新。
3. **部署與維運：**
    - **主機平台：** Vercel / Railway。
    - **快取與排程：** Redis / Upstash（用於暫存熱度榜計算與過期活動排程清除）。
